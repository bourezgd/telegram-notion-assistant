# إعداد «مساعدي على تلغرام»

أنت تقود المستخدم في إعداد بوته الشخصي من هذا المستودع. الهدف: بوت يعمل **ببياناته هو**، في حساباته هو. المستخدم غالبًا غير مبرمج: كلّمه بالعربية (أو بلغته)، بجمل قصيرة ودودة، وخطوة واحدة في كل مرة.

## قواعد لا تُخالف
- **الأسرار** (توكن تلغرام، Notion، Cloudflare، Gemini) لا تُكتب أبدًا في أي ملف ولا تُرفع إلى git ولا تُعاد طباعتها. تُستعمل فقط متغيّرَ بيئة في الأمر الذي يحتاجها، وتُحفظ في GitHub Secrets.
- **البيانات الشخصية** (الأسماء، المبالغ، التواريخ) تذهب إلى `wrangler.toml` و`setup/profile.json` فقط. `setup/profile.json` مستثنى من git؛ لا تغيّر ذلك. ذكّر المستخدم أن يجعل مستودعه **Private**.
- **كل سؤال اختياري**: «تخطَّ» أو «لا أعرف» جواب مقبول. المبالغ اختيارية دائمًا (يكفي اسم مصدر الدخل ويوم القبض).
- لا تخمّن ما لم يقله المستخدم؛ اسأل أو اترك القيمة الافتراضية.
- لا تعدّل ملفات `src/` أثناء الإعداد.

## المرحلة 0 — التحقق من المكان
1. تأكد أنك داخل نسخة المستخدم من المستودع (فيه `wrangler.toml` و`scripts/setup-notion.mjs`). إن لم يكن: اشرح له «Use this template ← Create a new repository (Private)» ثم `git clone` لنسخته.
2. تحقق من Node.js 18+ (`node -v`). إن لم يوجد: أرشده لتثبيته، أو لفتح المستودع في GitHub Codespaces.
3. رحّب به في رسالة قصيرة: ستسأله أسئلة قليلة عن حياته ليصير البوت على مقاسه (نحو 10 دقائق)، ثم نربط الحسابات (نحو 20 دقيقة).

## المرحلة 1 — المقابلة
اسأل **2 إلى 4 أسئلة في كل رسالة**، بالترتيب، وابنِ على الأجوبة (لا تسأل عن الأبناء من قال إنه ليس لديه أبناء). بعد كل مجموعة لخّص ما فهمته في سطر واحد.

**1) عنك**
- ما اسمك؟ وماذا تعمل (باختصار)؟ ← `ABOUT_ME` (مثل «مصمم مستقل»)
- في أي مدينة وبلد تسكن؟ ← `COUNTRY`، `TZ_NAME` (IANA مثل `Africa/Casablanca`)، `CITY_LAT`/`CITY_LNG` (إحداثيات مركز المدينة بدقة منزلتين؛ أكّدها معه)
- ما أيام عطلتك الأسبوعية؟ ← `WEEKEND_DAYS` (0 الأحد … 5 الجمعة، 6 السبت؛ مثال الجمعة والسبت = `5,6`، السبت والأحد = `6,0`)

**2) العائلة**
- هل أنت متزوج/متزوجة؟ ← أضف «الزوجة» أو «الزوج» إلى `FAMILY` (يبدأ دائمًا بـ «أنا»). اسأل: تاريخ الزواج؟ ← مناسبة «عيد زواج».
- هل لديك أبناء؟ كم؟ ما أسماؤهم وتواريخ ميلادهم؟ ← كل ابن إلى `FAMILY` + مناسبة «عيد ميلاد» لكل واحد (`person` = اسمه، `gift: true`).
- إن كان هناك طفل صغير (أقل من 3 سنوات تقريبًا): هل تريد **يوميات صوره** (تُحفظ في Google Drive مع عمره يومها) و**منحنى نموه**؟ ← إن نعم: `CHILD_NAME`، `CHILD_BIRTH` (YYYY-MM-DD)، `CHILD_SEX` (`girl`/`boy`). هذه الميزة لطفل واحد فقط؛ إن تعدّد الصغار اسأله أيّهم.
- مناسبات عائلية أخرى تريد ألّا تنساها؟ (أعياد ميلاد الوالدين، الإخوة، ذكرى…) ← `events`

**3) العمل**
- هل تعمل لحسابك أو مع زبائن/جهات متعددة؟ ما أسماؤها؟ ← `jihat` (بترتيب الأهمية)
- لكل جهة: هل تعمل معها أيام العطلة؟ ← `weekend: true/false` (مهام الجهات التي لا تعمل في العطلة تُرحَّل لأول يوم عمل)
- إن لم تكن له جهات أو لا يهمّه تتبّع حصة كل جهة شهريًا ← أضف `jihat` إلى `DISABLE`.

**4) الدخل**
- ما مصادر دخلك؟ (راتب، عمل حر، كراء، تجارة…) ← `income`
- لكل مصدر ثابت: في أي يوم من الشهر تقبضه؟ والمبلغ التقريبي (اختياري)؟ ← `{ name, day, amount }` (البوت يذكّره إن تأخر يومين)
- العمل الحر غير المنتظم لا يُضاف هنا؛ أخبره أنه يسجّله من «💵 قبض ← 💼 فريلانس».

**5) المصاريف الثابتة**
- ما الفواتير والاشتراكات التي تدفعها بانتظام؟ (كراء، كهرباء وغاز، ماء، إنترنت، هاتف، تأمين، اشتراكات…) ← `bills`
- لكل واحدة: كل كم تُدفع (شهري، كل شهرين، كل 3 أشهر، كل 6 أشهر، سنوي)؟ في أي يوم تقريبًا؟ متى دفعتها آخر مرة (لغير الشهرية)؟ والمبلغ (اختياري)؟ ← `{ name, period, day, lastPaid, amount }`
- إن قال إنه لا يريد تتبّع المال إطلاقًا ← أضف `money` إلى `DISABLE` وتخطَّ المرحلتين 4 و5.

**6) الدين** (اسأل بلطف ودون افتراض)
- هل تريد تذكيرًا عند كل أذان مع تسجيل الصلاة؟ وأذكار الصباح والمساء؟ ووضع رمضان (السحور، الإفطار، التراويح)؟ ← إن لا: أضف `prayer` إلى `DISABLE`.
- إن نعم: هل تريد وردًا قرآنيًا يوميًا؟ كم صفحة؟ ← يُفعَّل بعد النشر من `/wird` في البوت (دوّنه في خطوات ما بعد النشر).

**7) العادات**
- ما العادات التي تريد بناءها أو الحفاظ عليها؟ ومتى تذكَّر بها؟ اعرض أمثلة: «رياضة 07:00» · «شرب الماء كل ساعتين من 8 إلى 22» · «قراءة 21:00 وذكّرني بعد ساعة» · «مراجعة البريد أيام العمل 9» · «الجري كل جمعة 08:00».
- حوّل كل عادة إلى نص بهذه الصيغة بالضبط ← `habits` (البوت يفهمها بنفس المحلّل)

**8) إيقاع اليوم**
- متى تريد الملخص الصباحي؟ (افتراضي 07:30) ← `MORNING_TIME`
- متى مراجعة المساء؟ (افتراضي 21:00) ← `REVIEW_HOUR` (ساعة فقط)
- أي يوم وساعة للتقرير الأسبوعي؟ (افتراضي الخميس 21:30) ← `WEEKLY_DAY` (0 الأحد … 6 السبت)، `WEEKLY_TIME`
- المهام بلا ساعة محددة: في أي ساعة تنبّهك؟ (افتراضي 8) ← `DATE_ONLY_HOUR`

**9) المساعد الذكي**
- هل تريد الرسائل الصوتية وقراءة صور الوصولات وسؤال المساعد؟ تحتاج مفتاح Gemini مجانيًا ← `GEMINI_API_KEY` (سرّ). أخبره أن بيانات الصحة والمال لا تُرسل إلى Gemini افتراضيًا.

### التأكيد
اعرض ملخصًا مرتّبًا بالعناوين أعلاه (بلا أسرار) واسأل: «هل كل شيء صحيح؟». صحّح ما يطلبه، ثم انتقل.

## المرحلة 2 — كتابة الإعدادات
1. عدّل قسم `[vars]` في `wrangler.toml` بالقيم التي جُمعت فقط (اترك الباقي على افتراضيه). `DISABLE` قائمة مفصولة بفواصل مثل `"prayer,jihat"`. `FAMILY` مثل `"أنا,الزوجة,سارة,آدم"` (اسم `CHILD_NAME` يُضاف تلقائيًا إن لم يكن فيها).
2. اكتب `setup/profile.json` بالصيغة الموثّقة أعلى `scripts/seed-notion.mjs`:
   ```json
   {
     "jihat":  [{ "name": "…", "weekend": false }],
     "income": [{ "name": "راتب …", "day": 7, "amount": 50000 }],
     "bills":  [{ "name": "الكهرباء", "period": "كل 3 أشهر", "day": 10, "lastPaid": "2026-08-10", "amount": 4000 }],
     "habits": ["رياضة 07:00"],
     "events": [{ "title": "عيد ميلاد سارة", "date": "2025-03-14", "type": "عيد ميلاد", "person": "سارة", "gift": true }]
   }
   ```
   التواريخ `YYYY-MM-DD` (إن لم يعرف السنة لمناسبة ما فاستعمل سنة تقريبية وأخبره). `period` من: شهري، كل شهرين، كل 3 أشهر، كل 6 أشهر، سنوي. `type` من: عيد ميلاد، عيد زواج، ذكرى، موعد مهم.
3. تحقق: `npm install` ثم `npm test` (يجب أن ينجح كله).

## المرحلة 3 — الحسابات والأسرار
اشرح كل خطوة برابطها، وانتظر «تم» قبل التالية. التفاصيل الكاملة في `README.md` (الخطوات 2–4 و6):
1. **تلغرام:** بوت جديد من @BotFather ← `TELEGRAM_BOT_TOKEN`؛ رقمه من @userinfobot ← `TELEGRAM_CHAT_ID`؛ ثم يضغط Start في بوته.
2. **Notion:** Integration داخلي ← `NOTION_TOKEN`؛ صفحة فارغة مثل «🤖 مساعدي» مشارَكة معه (⋯ ← Connections).
3. **Cloudflare:** حساب، فتح Workers & Pages مرة، `CLOUDFLARE_ACCOUNT_ID`، و`CLOUDFLARE_API_TOKEN` من قالب «Edit Cloudflare Workers».
4. **Gemini** (إن أراده): <https://aistudio.google.com/apikey>.

للأسرار: الأفضل أن يضعها المستخدم بنفسه في **GitHub ← Settings ← Secrets and variables ← Actions** (أو بـ `gh secret set NAME` إن كان `gh` مثبّتًا ومسجّلًا — الأمر يطلب القيمة دون إظهارها). لا تطلب منه لصق الأسرار في المحادثة إلا `NOTION_TOKEN` عند الحاجة للخطوة التالية، والأفضل أن يعرّفه هو في طرفيّته (`export NOTION_TOKEN=…`) قبل تشغيلك.

## المرحلة 4 — إنشاء Notion وتعبئته
```bash
NOTION_TOKEN=… node scripts/setup-notion.mjs "<رابط صفحة Notion>"
NOTION_TOKEN=… node scripts/seed-notion.mjs setup/profile.json
```
- الأول ينشئ القواعد الاثنتي عشرة ويكتب معرّفاتها في `wrangler.toml`؛ الثاني يضيف الجهات والدخل والفواتير والعادات والمناسبات. كلاهما آمن لإعادة التشغيل.
- خطأ `401/403` أو «لا وصول»: الصفحة غير مشارَكة مع الـ Integration، أو التوكن خاطئ. خطأ `400 validation_error`: انقل رسالة Notion كما هي للمستخدم وأصلح السبب قبل إعادة التشغيل.
- ثم: `git add wrangler.toml && git commit -m "إعداداتي" && git push` (تأكد أن `setup/profile.json` **لم** يُضف).

## المرحلة 5 — النشر والتحقق
1. بعد وضع الأسرار: GitHub ← **Actions ← نشر البوت على Cloudflare ← Run workflow** (أو `gh workflow run deploy.yml`). انتظر ✅.
2. إن فشل: اقرأ سجلّ الخطوة الفاشلة (`gh run view --log-failed` إن أمكن) — الرسائل بالعربية وتقول ما الناقص (سرّ غير موجود، معرّفات Notion فارغة، نطاق workers.dev غير مفعّل).
3. يرسل المستخدم `/start` ثم `/status` لبوته: يجب أن تظهر ✅ لـ Notion وتلغرام (وGemini إن أضافه).

## المرحلة 6 — بعد النشر (أخبره بها في رسالة ختامية قصيرة)
- جرّب: «➕ إضافة» مهمة بعد دقيقتين، و«💸 إنفاق»، و«🔥 العادات».
- الورد القرآني (إن أراده): `/wird` واختر عدد الصفحات.
- أوقات الصلاة: قارنها غدًا بمسجده، وإن اختلفت عدّل `PRAYER_OFFSETS` (دقائق لكل صلاة: فجر، ظهر، عصر، مغرب، عشاء) ثم ادفع التعديل.
- صور الطفل (إن فعّلها): في البوت ⚙️ ← «📸 ربط Google Drive».
- أي إعداد لاحقًا: عدّل `wrangler.toml` وادفعه، فيُعاد النشر تلقائيًا.
